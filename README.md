# ORB 特征提取 + BFMatcher 匹配

学习项目：从零实现「ORB 特征提取 → 二进制描述子暴力匹配 → RANSAC 几何校验」的完整流程，
并在三组人工构造的对照实验上验证效果。

目的是搞清楚**每个环节到底在做什么、参数为什么这么设、什么时候会失效** ——
所有结论都基于本项目实测，不做"书上说 ORB 尺度不变性差"这类未经验证的转述。

> 算法原理与数据结构的详细笔记见 [`base.md`](base.md)。

## 代码结构

```
orb.py
├── load_image(name)              imread + 转灰度，失败即退出
├── detect(gray, orb)             ORB 检测 → (kp, des)
├── match_bfm(des1, des2)         BFMatcher(NORM_HAMMING, crossCheck)
├── sort_matches(matches, n)      按 distance 升序取前 n
├── run_pair(name, f1, f2, orb)   串起一组配对的完整流程
├── draw(..., wait_ms, title)     drawMatches + 窗口显示
└── main()                        解析 argv，遍历 PAIRS
```

数据流：

```
图像文件 → imread → BGR数组 → cvtColor → 灰度图
    → orb.detectAndCompute → kp(关键点) + des(描述子 500×32 uint8)

    ── 第一级过滤：局部纹理相似度 ──
    → bf.match(des1, des2) → list[DMatch]（按汉明距离）
    → sorted(distance)[:30]  → 可视化用

    ── 第二级过滤：全局几何一致性 ──
    → 取出 kp[queryIdx].pt / kp[trainIdx].pt → (N,2) float32
    → cv2.findHomography(..., cv2.RANSAC, 3) → H, mask
    → inliers = [m for m, k in zip(matches, mask.ravel()) if k == 1]
```

**两级过滤是独立的**：第一级看局部纹理像不像（描述子层面），
第二级看全局位置关系是否自洽（坐标层面）。谁也替代不了谁。

## 实测基准

固定条件：`nfeatures=500`，`TOP_N=30`，`cvtColor` 读灰度，RANSAC 阈值 3 像素。

### 关键点数量

| 图片 | 尺寸 | 关键点数 |
|---|---|---|
| `a_original` | 1200×900 | 500（取满 = 被上限截断） |
| `a_rotated` | 1500×1500 | 500 |
| `b_original` | 1200×900 | 500 |
| `b_scaled` | 300×225 | 453 |

### 三组配对

| 配对 | 匹配数 | 最小距离 | 中位距离 | RANSAC 内点 | **内点率** |
|---|---|---|---|---|---|
| **旋转 40°** | 279 | **7.0** | **27.0** | 223 | **79.9%** |
| **尺度 0.25×** | 157 | 28.0 | 67.0 | 26 | **16.6%** |
| **无关**（负对照） | 130 | 14.0 | 65.0 | 7 | **5.4%** |

**汉明距离刻度**：0 = 完全相同；8~20 = 高度确信；~64 = 常用阈值；**~127 = 随机水平**
（256 位里约一半不同）。注意 `match()` 返回的是"从 500 个候选里挑出的最近者"，
所以即使是无关图，中位距离也远低于 127 —— 这是**选择效应**，不是匹配质量的证据。

## 关键结论

### 1. `normType` 必须改成 `NORM_HAMMING`

`cv2.BFMatcher()` 的默认值是 `NORM_L2`（给 SIFT 浮点描述子用的）。
ORB 是 256 位二进制串，用欧氏距离**没有物理意义**。

可怕之处：**不报错、不崩溃，照样出结果**，只是大多是错的。
判别方法：看 `matches[0].distance`，用错 L2 时约 **218**，用对 Hamming 是**几十**。

### 2. `match()` 返回的顺序不是按距离排的

它按 query 描述子的原始顺序返回。`matches[0]` 的含义只是"第一个存活点的最佳匹配"，
**不是全局最好的匹配**。所以必须自己 `sorted(key=lambda m: m.distance)` 再切片。

### 3. ORB 的尺度不变性只在金字塔覆盖范围内有效

`nlevels=8`、`scaleFactor=1.2` → 覆盖 `1.2^7 ≈ 3.58` 倍尺度变化。实测退化曲线：

| 缩放比 | 需要的层数 | 中位距离 |
|---|---|---|
| 0.5 | 3.8 | 17 |
| 0.35 | 5.8 | 30 |
| **0.25** | **7.6** | **55** ← 顶到 8 层天花板 |
| 0.18 | 9.4 | 62（超出覆盖） |
| 0.12 | 11.6 | 67（超出覆盖） |

**0.5 倍时 ORB 依然匹配良好。**"ORB 尺度不变性差"只在**超出覆盖范围**时才成立。

### 4. RANSAC 有 5%~6% 的**噪声地板**

这是本项目最重要的发现。RANSAC 的机制是"随机抽 4 个点 → 拟合 → 数支持者"，
而单应矩阵 8 个自由度 ÷ 每点 2 个方程 = **4 个点就足以确定一个解**。

结果是：**RANSAC 永远不会返回 0 内点。**

实测 8 次无关图（6 个随机种子 × 有字/无字两种变体）：

```
内点率: 5.9%  4.5%  5.6%  6.4%  5.9%  4.7%  5.6%  5.8%
        └────────── 4.5% ~ 6.4% ──────────┘
内点数:  6~9（全都只比下限 4 多一点点）
```

**推论：判断"有没有真匹配"，不能看内点是否存在，要看内点率离地板有多远。**

| | 内点率 | 相对地板 |
|---|---|---|
| 无关 | 5.4% | 1× |
| 尺度 0.25× | 16.6% | 3× |
| 旋转 40° | 79.9% | **15×** |

> 推广：**任何阈值型算法，都要先测负样本的基线，再定阈值。**
> 只看正样本的数字，永远不知道自己离噪声有多近。

### 5. 无关图上的内点是**退化的假象**

实测 `a_original` vs `b_original`，RANSAC 返回的 `H` 把整张 1200×900 图映射到了一点：

```
H 的行列式 = -0.05（≈ 0，矩阵奇异）
奇异值     = [796.6, 0.307, 0.0002]   条件数 = 3.8e6

用 H 变换图1的四个角：
   (   0,   0) -> ( 450.0, 655.9)
   (1200,   0) -> ( 433.0, 622.1)
   (1200, 900) -> ( 431.5, 620.5)
   (   0, 900) -> ( 435.0, 623.7)     ← 全挤在 20 像素内
```

那 7 个"内点"在图 1 里散布全图，在图 2 里**全部撞在 (433, 620) 附近**。
所以画出来的线是**从四面八方汇聚到一个点**，不是真匹配。

### 6. 被实验推翻的假设（记录在案，避免重复踩坑）

| 假设 | 检验方式 | 结果 |
|---|---|---|
| 无关图的匹配来自两图**共享的文字素材** | 生成只有词汇不同的变体，6 个种子对照 | ❌ **推翻**。删光文字后匹配数 133 vs 137、最小距离 21.3 vs 21.7、中位距离 62.7 vs 64.5，**无差异** |
| `\|det(H)\| ≈ 0` 可判别退化 | 8 组无关图实测 | ❌ **推翻**。取值 7e-01、9e+00、5e-05、8e-02…… 无关图也有接近 0.7 和 9 的 |
| `H` 把四角摊开的面积可判别退化 | 同上 | ❌ **推翻**。无关图有取到 5142 px 的，**超过真匹配的 2095 px** |
| 全局标准差能测出关键点聚团 | 500 个关键点 vs top200 匹配点 | ❌ **推翻**。σ=289/196 vs 294/202，几乎相同。改用网格直方图才看出一个 60×60 格子塞了 100 个点 |
| 棋盘格区域描述子相似（"双胞胎"）导致歧义 | 区域内两两距离 | ❌ **推翻**。棋盘格 126.1 vs 非棋盘格 126.0，无差异（ORB 描述子带方向，`.angle` 各不相同） |

> 前三条的失败原因是同一个：**假内点对应的 `H` 是用 6~9 个点拟合的**，
> 勉强超过下限 4，极度不受约束 —— 它可以退化，也可以疯狂放大，
> **没有稳定特征可抓**。

### 7. 匹配点扎堆是**检测环节**的问题，不是匹配环节

FAST 角点只在有纹理处点火，而 ORB 按 `.response` 取前 500 个，
**最密集的纹理区垄断了配额**。实测 `a_original`（60×60 网格）：

- 全部 500 个关键点占用 49/300 个格子（16%），最密的一个格子塞了 **100 个点（20%）**
- top200 匹配点占用 37/300（12%）

**匹配继承了这个集中，但没有制造它。**

## 已知问题

### A. 代码问题（已定位，未修复）

| # | 位置 | 问题 | 后果 |
|---|---|---|---|
| **1** | `orb.py:60` vs `63-64` | **空匹配的"保护"写在 `findHomography` 之后** | **保护永远不生效** —— 匹配为空时第 60 行先崩，根本走不到第 64 行。位置必须前移 |
| **2** | `orb.py:65` | 匹配为空时 `np.median([])` | 返回 **`nan`**，并抛 `RuntimeWarning: Mean of empty slice`（实测） |
| **3** | `orb.py:60` | `H is None` 未判断 | 点数 ≥4 但几何退化时（如所有点重合），`findHomography` 返回 **`(None, None)`**（实测），后续 `mask.ravel()` 会 `AttributeError` |
| **4** | `orb.py:64` | 变量名 `temp` | 语义不明，三个月后看不懂它是"最佳匹配的汉明距离" |
| **5** | `orb.py:66` | 打印了内点**数量**，没打印**比例** | 无关组的 7 个和旋转组的 223 个看起来只差数量级，看不出 5.4% vs 79.9% 的本质区别 |
| **6** | `orb.py:68-69` | 内点率低于地板也照画 | 无关组画出 7 条假线，**视觉上误导**，违反了本项目实测出的 5%~6% 噪声地板 |
| **7** | `orb.py:84-88` | 组名敲错时静默走完全部循环、什么都不输出 | "什么都不发生"是最难 debug 的失败模式 |
| **8** | `orb.py:46-47` | 同一张图跨组重复检测 | `a_original` 在"旋转"和"无关"两组里被 `imread` + `detectAndCompute` 各算一次，浪费（也是潜在的 bug 源：两处结果不一致时会很迷惑） |

**关于 #1 的详细说明**（最严重的一条）：

```python
H, mask = cv2.findHomography(src, dst, cv2.RANSAC, 3)      # ← 第 60 行：匹配为空时在这里就崩了
inliers = [m for m, k in zip(matches, mask.ravel()) if k == 1]

#保护，防止出现一个匹配都没有的情况，用999代表最小距离也无限大      ← 第 63-64 行：太晚了
temp = matches_topn[0].distance if len(matches_topn) > 0 else 999
```

实测 `findHomography` 在点数 **< 4** 时**直接抛异常**（不是返回 None）：

```
error: (-215:Assertion failed) npoints >= 4 ...
```

所以 `matches` 一旦为空，程序在第 60 行就终止了，第 64 行的 `if len(...) > 0` 永远得不到执行的机会。
**保护条件本身是对的，但它站错了位置。**

### B. 方法层面的局限

| 局限 | 说明 |
|---|---|
| **没有"拒绝"机制** | RANSAC 在纯噪声上必然产出 5%~6% 内点，`findHomography` 也从不报错。当前程序**没有能力说出"这组没有有效匹配"** |
| **固定 `TOP_N=30` 做可视化对比** | 旋转组有 223 个内点却只画 30 条，无关组只有 7 个内点也画 7 条 —— 两边的"信息密度"不对等，看图会失真 |
| **只假设单一几何关系** | 单应矩阵假设两图间是**一个平面**或纯旋转（相机光心不动）。有多个深度层次的真实场景里，这个假设会失效 |
| **阈值 3 像素未经标定** | 这个值是凭经验取的，没测过它对内点率的影响曲线 |
| **素材是合成的** | 渐变 + 噪点的统计特性和真实照片差异很大。真实照片有传感器噪声、镜头畸变、运动模糊、曝光变化 —— 本项目所有结论**只在合成素材上验证过** |

### C. 尚未验证的猜想（悬案）

> **为什么尺度组的最小距离（28）比无关组（14）还差？**

- `base.md` 第 8 节原来的解释（"无关组共享文字纹理，撞出零星真匹配"）**已被实验推翻**
  —— 见「关键结论」第 6 条的对照实验：删光文字后最小距离 21.3 vs 有字 21.7，无差异。
- 现有猜测：`b_scaled` 只有 300×225，缩小后纹理被抹平、描述子区分度下降，
  导致"最像的一对"也不够像。而无关组是两张**全尺寸、纹理丰富**的图，
  500×500 个描述子里总能撞出几对巧合。
- **但这个猜测没有测过。** 验证思路：统计两张图各自描述子的**近邻距离分布**，
  看 `b_scaled` 是不是整体右移。

## 重构验证纪律

本项目**没有自动化测试**，所以每次改动结构后，靠下面三组数字做回归：

```
旋转  279  7.0  27.0
尺度  157  28.0  67.0
无关  130  14.0  65.0
```

（依次为：匹配数、最小汉明距离、中位汉明距离）

**规则：纯重构不得改变这三个数字。** 数字变了，要么引入了 bug，
要么改了会影响结果的东西（比如灰度读法从 `cvtColor` 换成 `IMREAD_GRAYSCALE`，
实测会让匹配数从 279 变成 274 —— 两种读法都没错，但**前后必须一致**）。

这套纪律在重构 `PAIRS` 数据结构和拆函数时各抓到过一次错误。
